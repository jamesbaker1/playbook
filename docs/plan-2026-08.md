# Consolidated plan — August 2026

*Synthesizes three reviews conducted 2026-08-02: a strategic read of the engine,
docs, and training stack; a survey of the legal-AI benchmark landscape; and a
detailed UX walkthrough of the web gym. Supersedes nothing — ROADMAP.md remains
the phase ledger; this is the working plan for the next push and the launch.*

## Where the project stands

The engine, scoring contract, and matter set are in good shape: v0.3 shipped
escalation and deterministic negotiation, ten public matters with reference and
adversarial trajectories under CI, a private held-out split, a consent-gated
replay-verified human-trace pipeline, and Modal-ready training scaffolds. The
two big deficits are **evidence** (no baseline numbers have ever been run — no
model scores, no human scores, no proof the trap counter traps) and **web-client
parity** (the browser exposes five of nine action types; the two v0.3 matters
that showcase judgment mechanics are listed but not completable in the UI).
Positioning has also shifted under us: Harvey's LAB (MIT, rubric-graded, static)
and Crosby's closed negotiation bench mean the claim is no longer "the only
agentic legal benchmark" but **"the only interactive, deterministic legal
gym"** — partially observable, budgeted information-gathering, scripted
counterparty, no LLM judge in the reward path.

## Track A — Web gym: launch blockers and shareability

Ordered by leverage; A1–A5 are the launch gate.

- **A1. Link previews.** OG + Twitter card meta tags, favicon, and a real
  `og:image`. The acquisition channel is a shared link; today it unfurls as a
  bare grey text card.
- **A2. Visible failures and busy states.** A failed step currently writes the
  error into a hidden pane and does nothing else. Surface errors (switch to
  Activity, offer retry), and add the missing `[aria-busy]` CSS so the
  replay-per-step latency reads as work, not deadness.
- **A3. Client-side citation and quote checks.** The client already holds
  `obs.documents` and the verbatim text of every opened section; validate
  `document §section` syntax before submit and diff quotes against the cited
  section (same normalization as the scorer) with a warn-before-submit. A
  non-verbatim quote is a score-capping critical failure the UI currently lets
  users walk into blind. Add a way to insert `§` and a "copy citation" affordance
  on sections.
- **A4. v0.3 parity: escalate + negotiation in the client.** Add `escalate`,
  `send_markup`, and `accept_counterparty` controls, driven off the
  `action_schemas` the engine already sends rather than a hardcoded tab list;
  render `escalations_remaining`, `negotiation_rounds_remaining`, and the
  per-label negotiation map. Until merged, `nego_saas_010` and
  `msa_provider_004` must carry a "CLI-only" marker or be hidden from the
  dropdown — shipping matters whose assignments describe buttons that don't
  exist is the worst experience in the product.
- **A5. Episode guard.** Confirm before `start matter` abandons a live episode;
  `beforeunload` while an episode is active. Consider localStorage action-log
  persistence (the engine replays deterministically, so resume is cheap).
- **A6. Score screen as the shareable artifact.** Itemize the offending
  citations and fabricated quotes (the arrays are already in the breakdown —
  only counts are shown); map rubric criterion IDs to human-readable names; add
  a header row to the audit table; un-collapse the audit. Then build the
  **result card**: a clean, copyable/downloadable score summary designed to be
  posted — this is the growth loop for the LinkedIn launch, and today no
  postable artifact exists.
- **A7. Workflow polish.** After submitting an issue, land on Review (the pane
  that just gained the card), not the raw Activity log. Render `learned_facts`
  as a persistent facts panel — client answers are the scarcest resource in the
  game and currently live only as scrollback.
- **A8. Voice cohesion.** The splash is restored to the challenge voice and the
  training-data mission (done 2026-08-02). Remaining: sweep the residual
  sentence-case/lowercase clashes, restyle `contribute.js` to match the design
  system, and fix the consent copy — it says "anonymous" beside an optional
  handle field; say what actually happens (handle kept in raw storage, excluded
  from training exports).

## Track B — Evidence: the baseline sprint

Everything downstream — the launch post, the training go/no-go, the paper —
needs numbers. This is one blocked decision (API budget), then mechanical work.

- **B1. Model baselines.** `playbook-bench --runner baseline` across a spread of
  API models (frontier + open-weights via an OpenAI-compatible endpoint) on the
  public dev split, then the private held-out split. Report SPEC §10 metrics,
  including escalation recall and settled-issue quality; confirm the
  `nego_saas_010` trap counter actually traps capable models.
- **B2. Human baseline.** The author plus early lawyer testers play Benchmark
  mode; contributed traces flow through the verified pipeline. Even n=5 makes
  "humans vs. models" the headline of the launch post.
- **B3. Publish.** Scorecard table in the README and `docs/report.md`; the
  delta between dev and held-out splits is itself a finding.

## Track C — Data: growing the matter set without poisoning it

Conversion-of-schemas, not conversion-of-text. Public benchmark text (CUAD,
EDGAR-derived corpora) is in every pretraining set; making it load-bearing for
scoring would measure memorization. The synthetic-matters + canary + private
split design is the defense — keep it and say so loudly.

- **C1. Schema mining.** MAUD's 92 M&A deal points → scripted-counterparty
  position ladders (an M&A matter pack is the most distinctive expansion
  available); ContractNLI's hypothesis/evidence structure → hidden-fact and
  client-question design; CUAD's 41 clause categories → rubric coverage
  checklist for the existing tech-transactions matters.
- **C2. Style grounding.** Bonterms and Common Paper standard agreements
  (CC BY 4.0) as clean modern baselines to perturb; SEC EDGAR via the Stanford
  Material Contracts Corpus for structure and drafting-convention realism.
  Never anchor scoring on verbatim public text. Excluded: oneNDA (CC BY-ND),
  Law Insider (ToS).
- **C3. Harvey LAB adaptation experiment.** LAB is MIT-licensed and its
  in-house contracting tasks (contracts + playbooks + emails + redline rounds)
  are structurally adjacent. Adapt a batch into interactive episodes (add
  hidden facts, budgets, counterparty scripts) and publish the score delta:
  "static rubric grading vs. interactive environment" is a paper-worthy result
  and the sharpest possible positioning against the closest competitor.
- **C4. Human traces: what they are actually for.** With ten matters, human
  play yields hundreds-not-millions of episodes; that is a **human baseline, a
  rubric-calibration set, and SFT seasoning** — not a primary training corpus.
  The paid calibration pilot (5–10 practicing lawyers, ROADMAP Phase 5) is the
  next concrete step; measure rubric/expert agreement before soliciting scale.
- **C5. Lawyers as validators, not authors.** Practitioner hours go to auditing
  generated matters for realism, calibrating severities, and contributing trap
  clauses — not to drafting from scratch. This is also the credibility signal
  the field looks for.

## Track D — Training: go/no-go and sequence

The model is a *demonstration that the gym works as a training environment*,
not the product. The product is the environment + benchmark + data pipeline.

- **Go criteria:** baselines (B1) show real headroom below the reference
  trajectories; rollout cost is acceptable; adversarial suite passes on real
  rollouts. If frontier models already saturate the public split, the story
  pivots to the held-out split and harder matters, not to training.
- **D1.** Rollouts → filter (high-scoring, critical-free, legally reviewed) →
  LoRA SFT per `training/README.md`. **D2.** Preference pairs → DPO. **D3.**
  GRPO with environment-owned reward only after adversarial re-testing on real
  rollouts. All Modal, all explicitly approved per run, never automatic.
- Publish methods + limitations honestly (base vs. SFT on held-out matters).

## Track E — Expert data beyond the gym

- **E0. The gym is the sandbox.** For computer-use (pixels-to-actions) data:
  record *volunteers playing the web gym* — everything on screen is synthetic
  by construction, so the consent problem vanishes. Screen video aligned to
  ground-truth semantic traces and scores. This is the only near-term screen
  recording worth doing, and it is a novel dataset in its own right.
- **E1. Semantic capture at firms** per `docs/activity-capture.md`: capture
  actions, not pixels; Word/DMS add-ins on allowlisted consented matters;
  events in the existing trace schema. Blanket screen recording — including
  "record everything, filter later" — stays rejected: the capture is the
  violation, the archive is the liability, and post-hoc filtering can't be
  audited without more exposure.
- **E2. Matter compiler Phase A** (`docs/matter-compiler.md` §6): the synthetic
  evidence-bundle generator — fabricate a `.docx` version chain + threads for an
  existing matter, compile it back, and measure how much of the hand-authored
  rubric the pipeline recovers. Zero firm access, publishable, and it
  de-risks the whole compiler thesis.

## Track F — Launch

Gate: A1–A5 fixed, B1 numbers in hand, README claims reconciled with what the
web client actually does (today the README overstates parity).

Launch package: the play link (unfurling into a real card), a humans-vs-models
scorecard, one shareable result artifact, and the positioning line — *the only
interactive, deterministic legal gym; every episode is auditable training
data; contribute a trace if you think you can beat the models.* Invite
practitioners to play Benchmark mode and opt in. The contribute flow's consent
copy must be honest before the invitation goes out (A8).

## Sequencing

1. **Now:** A1, A2, A3, A5 (small, independent); A4 behind them; A6–A8 next.
2. **Parallel:** B1 the moment an API budget is approved; E2 and C1 are
   engine-side and independent of the web work.
3. **Then:** launch (F) once A-gate + B1 close.
4. **After launch:** C3/C4 (the pilot benefits from launch traffic), D per its
   go criteria, E0/E1 as partners appear.
